How to learn, run and get the most out of Kite Terminal

Kite Terminal is a semi-automated trading assistant. It scans your NSE watchlist after the close, puts every proposed trade in front of you for approval, sizes it against your risk limits, places the protective stop, trails it and reconciles with Zerodha. You decide what gets traded. This page gives you a training path, a daily routine, the doc to read for each job, what to verify, and how to use the app well.

Ticks on this page are saved only in this browser. The daily-routine ticks clear themselves each new day.

RULE 1
Nothing trades without your clickEvery signal and manual trade becomes a ticket you approve in a confirmation dialog.
RULE 2
Dry Run until the Journal says otherwiseStay in paper mode until your Dry Run Journal shows positive expectancy over 30 or more trades.
RULE 3
Kite is the source of truthWhen the app and the broker disagree, look at Kite first. Reconciliation flags it and never auto-corrects.
RULE 4
Lock first, investigate secondThe trading lock blocks only new entries. Exits, stops and monitoring keep running.
RULE 5
Never resubmit an UNKNOWN orderA duplicate real order is worse than a delayed one. Wait for the order monitor's verdict.
RULE 6
Never edit the database by handEvery state has a supported path in the UI. Back up before any code change.
The mental model

How a trade moves through the app

The app automates all of these steps except one: the approval is yours. Once you know which part does what, you know where to look when something seems wrong.

Automatic · 16:00 IST

Sync data

The Autopilot downloads the day's daily candles for watchlist and holdings, checks freshness and expires stale signals.

Automatic

Strategy scan

Momentum Breakout and Trend Pullback look for entries. Exit and breakeven checks run on open positions.

Automatic

Risk engine

Runs six checks: R:R, capital per trade, stock and sector exposure, open positions, portfolio risk. Signals that fail go to "Blocked by risk".

You

Approvals

Open Signal Detail, read the evidence, then Approve and place, or Reject.

Automatic

Execution

Places a LIMIT entry (or AMO). In Dry Run this is a PAPER-O-… paper order. When it fills, the app places a protective GTT.

Automatic · every 20–180 s

Guard

The order monitor checks every 20 s, the trailing stop every 45 s and reconciliation every 3 min.

Automatic

Journal

A position closes only after the broker confirms the exit. Results land in the Journal, with Dry Run and Live kept separate.

The screens, and what each one is for

Dashboard Overview

Portfolio, holdings, day P&L, alerts for concentration, losses, session expiry and low margin.

Approvals Daily

Your inbox: entry signals, exit signals, stop adjustments, signals blocked by risk, and the Autopilot run log.

Today's Actions Daily

Pre-market briefing: buy and exit candidates, breakeven adjustments, and a list of stocks near a breakout.

Positions Daily

Lifecycle state for each position (ENTRY WORKING → OPEN → EXITING → CLOSED), whether it's protected, and its GTT. You can cancel a working order here.

Trade Queue

Tickets grouped as ready, waiting, rejected or executed, plus reconciliation findings that need "Mark reviewed".

Orders & Trades

The broker order book, fills and GTTs, each linked to its ticket. You can cancel from here.

New Ticket

Manual trades. They go through the same risk checks, sizing and confirmation as strategy signals.

Watchlist

The universe the scans run on. Shows price, trend, RSI-14 and distance to the 20-day high. Holdings are always included.

Price-Volume Research

Describes volume evidence across the watchlist (RVOL, OBV, traded value). It's a research tool and does not generate signals.

Strategies Weekly

Enable or disable strategies, edit parameters (each change is versioned), Scan Now, and the realistic Backtest.

Journal Weekly

Win rate, expectancy in R, profit factor, drawdown and equity curve, broken down by strategy and symbol.

Ticket History

Full audit log you can filter by status, source, symbol and date.

Settings

Risk limits, account safety (max order value, ₹ daily loss, entries per day), and sector mappings.

Live Readiness Before live

Read-only pre-flight with 30+ checks. Answers READY or NOT READY for a live entry.

Diagnostics Daily

Schema, integrity, worker health, session, flagged price history (with Rebuild history).

What to do daily

The daily routine (IST)

The strategies trade on daily candles, so this isn't screen-watching. Most of the work is a short morning check and an evening review of what the Autopilot found. The background workers handle everything during the session.

0 of 0 done today ·
08:30 – 09:10Pre-market · 15 min

Start, log in, health check

09:15 – 09:45Market open · 10 min

Act on pending signals

09:45 – 15:30Session · hands off

Let the guards work

The order monitor (20 s), trailing engine (45 s) and reconciliation (3 min) run on their own. Glance at the alert banner and Positions badge now and then. If something looks wrong, lock trading first. Don't manually trade the same stocks in Kite, because reconciliation will flag the mismatch.

16:00Autopilot · automatic

Post-close pipeline

Sync candles → check freshness → expire stale signals → run every enabled strategy → queue tickets. The app must be running and logged in. If it was off, the run catches up the next time you start the server or log in.

16:15 – 21:00Evening review · 20–30 min

The decision window

Weekly, monthly, yearly

Weekly (weekend, 30–45 min)

  • Journal: expectancy and profit factor by strategy and by symbol.
  • Database backup: python -m backend.db_maintenance backup, then integrity.
  • Price-Volume Research: review the watchlist, and drop names with low traded value.
  • Settings → Sector mappings: map any new symbols.
  • Diagnostics → Historical price data: rebuild any NEEDS_REFRESH symbols (splits or bonuses).
  • Skim logs/kite_terminal.log for errors.

Monthly

  • Backtest each enabled strategy over the latest 6–12 months, with walk-forward. Read the net figures.
  • Compare live, paper and backtest expectancy. If they drift apart, find out why.
  • Review risk settings against your current capital.
  • Check python -m backend.db_maintenance status for size and schema, and run vacuum with the app stopped if needed.

Yearly (December) and after code updates

  • Add next year's NSE holidays to backend/calendar_data/nse_equity_holidays.json (DEPLOYMENT.md). Without them you'll see a CALENDAR_YEAR_UNCOVERED warning.
  • Before any code change: git tag + branch + DB snapshot. After it: run pytest and the relevant manual checks.
  • Re-run Live Readiness after any update.

Regression policy (TESTING §3) After any change to strategy logic, risk thresholds or execution code: (1) run the full pytest; (2) re-run the matching manual section (C for strategy, B for risk, F for execution); (3) for parameter changes, run a fresh backtest and compare with the baseline; (4) judge on net figures, since costs of about 0.08–0.10R per round trip can turn a strategy that's positive before costs negative; (5) prefer a value in the middle of a broad range that works in both halves of the data over the single best point.
Max advantage

How to get the most out of the app

The app helps you most by making each trade carefully, not by trading more often. These habits make the difference.

Never approve from the card alone

Signal Detail shows the exact candles the strategy used, each condition with its threshold, the six risk checks with real numbers, and how the size was calculated. One minute per signal there catches most bad trades.

A better watchlist gives better signals

The scans only see your watchlist and holdings. Keep it to liquid names you understand, and use Price-Volume Research to spot low traded value. The volume filters are what made both strategies profitable after costs.

Use the Smart Money score as context, not a ranking

Out-of-sample validation (PK-25) rated it LIMITED. Scores of 75 or more reduced expectancy in both test periods. Read the Volume context and Accumulation evidence to understand the bar, but don't filter or rank signals by the score.

Trust the revised defaults and don't over-tune

The September 2026 parameters were picked from the middle of ranges that worked in both halves of the data at costs up to 0.70%. A market-regime gate and a 52-week-high variant were tested and added nothing. Before changing a parameter, prove it with a net backtest and walk-forward.

Keep the Autopilot running

Keep the server running and logged in at 16:00 IST so the scan uses the day's final candle. If you miss it, starting the server or logging in catches up. Signals expire after a day, so review every evening.

Use all the safety controls

Use the trading lock, ₹ daily loss limit, max order value and 1 entry per day at first. They block only new entries, so you can be strict with them without risking getting stuck in a position.

Map every sector

An unmapped symbol skips the sector-exposure check without blocking anything. Clear the "unmapped symbols" helper every week so the risk engine can apply all six checks.

Act on exits and breakeven first

Exit signals and breakeven proposals protect profit you already have. Handle them before looking at new entries, every session.

Let the Journal decide

Check expectancy by strategy, not just the overall total. Ignore the numbers until there are at least 20 trades, and wait for 30 before going live. If a strategy is negative over a real sample, disable it, however good it looked in backtests.

Keep your data clean

Rebuild NEEDS_REFRESH symbols after splits and bonuses, since the live scan skips them. Back up weekly. The database holds your tickets, about 47k candles and the instrument cache, and git doesn't restore any of them.

Don't do these Run with --reload or more than one worker · expose port 8000 to the internet (the app has no login of its own) · resubmit an order whose outcome is UNKNOWN · place a second order to "fix" a partial fill · trade the same symbols by hand in Kite while the app manages them · edit kite_terminal.db by hand · enable RSI Mean Reversion live · rank signals by the Smart Money score.
When it goes wrong

Quick incident guide

For live incidents, lock trading first, then look at Kite itself. The full table is in FIRST_LIVE_TRADE.md → "If something goes wrong".

You seeIt usually meansDo this
"Session expired"It's a new trading dayLog in again. Kite requires a login every day.
Live order rejected, "IP not allowed"Your static IP isn't registeredDeveloper console → static IP, and Live Readiness → Static IP. Create a new ticket; the failed one can't be reused.
LIVE_PREREQUISITE_MISSINGNotional cap, ₹ daily loss, static IP, or an UNKNOWN orderOpen Live Readiness. It lists exactly which one.
SUBMISSION UNKNOWNThe network failed while the order was being sentLock. Do not resubmit. Search Kite's order book for the ticket's tag, and wait up to 15 minutes for the monitor's verdict.
Protection failed / UNPROTECTEDThe entry filled but the GTT couldn't be placedLock. Place a stop-loss in Kite immediately, then mark the finding reviewed.
ENTRY PARTIALOnly part of the order filledThe GTT already covers the filled quantity. Let the rest keep working or cancel it. Never place a second order.
Quantity mismatch / possible double sellThe app and Kite disagree about what you holdLock. Compare holdings and GTTs in Kite, delete any GTT on shares you no longer hold, then mark reviewed.
Circuit breaker OPENThe broker or connection failed repeatedlyFind the cause in Diagnostics and the logs. Reset only once you understand it.
A signal disappearedIt expired because it was based on an old candleNothing to do. This is intended, so you never approve against old prices.
INVALID_HOSTThe browser address isn't allowedUse 127.0.0.1:8000 or localhost:8000.
Something you can't explain—Lock trading and investigate. Use Emergency Exit (type EXIT ALL) only if every position has to be closed.

Database maintenance

python -m backend.db_maintenance status
python -m backend.db_maintenance integrity
python -m backend.db_maintenance backup
python -m backend.db_maintenance vacuum # app stopped!

Health endpoints (browser or curl)

  • /api/health: the process is up
  • /api/ready: ready to trade, or 503 with a list of blockers
  • /api/diagnostics: everything on the Diagnostics page
  • /api/live-readiness: the LIVE-0 pre-flight (?broker=true adds a read-only Kite snapshot)

Before changing any code

git tag backup-pre-<work> git branch backup/pre-<work> copy backend\kite_terminal.db backend\kite_terminal.db.pre_<work>_bak

The database isn't tracked by git, so a git backup alone only covers half of a rollback.
